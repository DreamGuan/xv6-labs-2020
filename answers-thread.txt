With two threads, two put operations may insert into the same hash bucket concurrently. Suppose both threads read the same old value of table[i]. Thread 1 creates entry A and sets A->next to the old head. Thread 2 creates entry B and also sets B->next to the same old head. Thread 1 then sets table[i] to A, but thread 2 subsequently sets table[i] to B. The second write overwrites the first update, so entry A is no longer reachable from the hash table and its key is reported missing. With one thread, these operations cannot overlap, so this lost-update race does not occur.
